Before v0.9.0-beta.14 the server read every cron expression as UTC. It now reads them in {{$.TZ}}, so a schedule saved before then fires at a different clock time than it used to. This rewrites the schedules you tick so they fire at the same clock time as before, at today's offset (daylight saving moves the old UTC schedules by an hour twice a year; from now on a schedule stays at its local time). Untick a job you already set in local time, for example by dragging it on the Schedule page. This can be done once: it is recorded, and the offer goes away.
